# Task 1: Voice message contracts and Telegram file boundary

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add adapter-independent voice input models, approved Russian copy constants, and a Telegram file download protocol with a fake implementation. This gives later tasks a live-SDK-free way to validate duration, download behavior, and user-facing responses.

## What to do

- Add voice-related request/result models in `app/services/voice_messages.py`.
- Add approved Russian copy constants for accepted voice, too-long voice, retry/fallback, and voice-without-active-draft cases in `app/bot/messages.py`.
- Add `TelegramFileDownload`, `TelegramFileDownloader`, and `FakeTelegramFileDownloader` to `app/bot/clients.py`.
- Keep boundary modules free from live Telegram, Google, OpenAI, Whisper, or other external SDK imports.
- Add tests for the new copy and fake download boundary.

## TDD Anchor

Tests to write BEFORE implementation. Write → run → confirm they fail → write code → confirm they pass.

- `tests/test_voice_processing_messages.py::test_voice_processing_copy_matches_approved_text`
- `tests/test_boundaries.py::test_fake_telegram_file_downloader_writes_requested_local_file`
- `tests/test_boundaries.py::test_boundary_modules_do_not_import_live_sdks`

## Acceptance Criteria

- [ ] Approved voice processing copy exists and is used through constants.
- [ ] Fake Telegram file downloader creates deterministic local test files without live SDKs.
- [ ] Boundary import regression still rejects live SDK imports.
- [ ] No application code imports real Telegram/transcription SDKs.
