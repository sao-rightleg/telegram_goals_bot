# Task 3: Voice processing service

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Implement the shared voice service that routes voice input to the active weekly report or insight draft, validates duration before download, stores audio locally, transcribes it, and handles failures without clearing drafts. This centralizes voice-specific behavior while leaving final business writes in existing flow services.

## What to do

- Implement `VoiceMessageService` in `app/services/voice_messages.py`.
- Use `DialogStateRepository` to detect active voice-capable flow.
- Reject over-limit voice before download/transcription/draft mutation.
- Build local audio paths with `StoragePathPolicy.audio_path(...)`.
- Use `TelegramFileDownloader` and `SpeechTranscriber` boundaries.
- Append accepted voice to the correct draft repository.
- Route technical failures through `NotificationRouter` and preserve active drafts.

## Acceptance Criteria

- [ ] Voice without active draft does not download or mutate state.
- [ ] Voice over 600 seconds is rejected before side effects.
- [ ] Weekly report voice is downloaded, transcribed, and appended to draft.
- [ ] Insight voice is downloaded, transcribed, and appended to draft.
- [ ] Failure paths preserve drafts and route technical details only to admin error chat.
