# Task 6: Boundary and regression tests

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add cross-flow tests for participant scoping, missing-data notifications, consent-before-data rules, and out-of-scope exclusions. This locks the core safety guarantees before audit.

## What to do

- Add integration/regression tests that span start, consent, menu actions, Sheets fake, notification router, and dialog state.
- Verify participant data scoping across multiple fake participants.
- Verify no business data is returned before consent.
- Verify missing-data admin notifications are routed through error bot only.
- Verify out-of-scope exclusions remain absent.
- Run the full test suite after the new regression tests pass.

## TDD Anchor

Tests to write BEFORE any corrective implementation. Write → run → confirm they fail only if coverage exposes a real gap → fix code → confirm they pass.

- `tests/test_participant_boundaries.py::test_participant_cannot_view_another_participants_goal_or_steps` — cross-participant data is isolated.
- `tests/test_participant_boundaries.py::test_no_business_data_before_consent_across_actions` — consent gate holds for all protected views.
- `tests/test_participant_boundaries.py::test_missing_required_data_routes_error_bot_only` — missing data notification route is safe.
- `tests/test_participant_boundaries.py::test_sqlite_contains_no_participant_business_tables_after_flows` — SQLite boundary remains technical.
- `tests/test_participant_boundaries.py::test_feature_does_not_introduce_out_of_scope_dependencies_or_artifacts` — no live SDK/deploy/PDF/voice/scheduler scope creep.
