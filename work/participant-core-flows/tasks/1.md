# Task 1: Participant domain and message contracts

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add typed domain objects, menu action constants, Russian message templates, and view formatters for participant core flows. This gives the service layer stable contracts and keeps user-facing copy centralized.

## What to do

- Add participant flow domain models for Telegram user context, participants, goals, planned steps, weekly status, menu items, and flow responses.
- Add stable menu action constants for participant, captain, inert insight, and captain-only placeholder actions.
- Add Russian message templates for approved unknown-user text, approved consent text, missing-data text, role menu rendering, goal view, planned-steps view, progress view, and not-yet-available actions.
- Add progress formatting for a 6-cell planned-step progress bar.
- Keep message formatting independent from live Telegram SDK types.

## TDD Anchor

Tests to write BEFORE implementation. Write → run → confirm they fail → write code → confirm they pass.

- `tests/test_participant_messages.py::test_unknown_user_message_matches_approved_copy` — exact approved unknown-user text is used.
- `tests/test_participant_messages.py::test_consent_message_matches_approved_copy` — exact approved consent text and `✅ Согласен` button are exposed.
- `tests/test_participant_messages.py::test_participant_menu_contains_approved_buttons_only` — participant menu matches approved scenario buttons.
- `tests/test_participant_messages.py::test_captain_menu_extends_participant_menu` — captain menu includes participant buttons plus captain buttons.
- `tests/test_participant_messages.py::test_progress_formatter_uses_six_cells_and_percent` — progress output contains six cells and calculated percent.
- `tests/test_participant_messages.py::test_missing_data_message_hides_internal_fields` — user-facing missing-data copy does not expose schema names or secrets.

## Acceptance Criteria

- [ ] Russian user-facing copy matches approved Telegram scenarios where exact text is specified.
- [ ] Menu action identifiers are stable and separate from Russian labels.
- [ ] Participant menu contains only participant buttons from the approved scenarios.
- [ ] Captain menu contains participant buttons plus approved captain buttons.
- [ ] Formatters are pure and testable without Telegram, Google, SQLite, or network access.
- [ ] No weekly report, insight submission, voice, PDF, scheduler, deploy, or live SDK code is added.
