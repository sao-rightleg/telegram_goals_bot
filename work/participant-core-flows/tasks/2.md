# Task 2: Participant Sheets boundary

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Extend the Google Sheets gateway protocol and fake implementation for participant identity, consent, active goal, planned steps, and weekly status history. This keeps all business facts behind the approved Sheets boundary.

## What to do

- Extend `SheetsGateway` with participant lookup, consent update, active goal read, planned-step read, and weekly status history read methods.
- Extend `FakeSheetsGateway` with in-memory rows for participants, goals, planned steps, weekly reports, and insights.
- Ensure fake reads return defensive copies.
- Ensure consent updates mutate the participant row identified by `participant_id`.
- Preserve existing weekly report and insight fake behavior used by foundation tests.

## TDD Anchor

Tests to write BEFORE implementation. Write → run → confirm they fail → write code → confirm they pass.

- `tests/test_participant_sheets_gateway.py::test_find_participant_by_telegram_id_returns_copy` — lookup works and returned row cannot mutate fake storage.
- `tests/test_participant_sheets_gateway.py::test_find_participant_by_unknown_telegram_id_returns_none` — unknown Telegram ID is absent.
- `tests/test_participant_sheets_gateway.py::test_update_participant_consent_updates_only_matching_participant` — consent write is scoped by participant ID.
- `tests/test_participant_sheets_gateway.py::test_get_active_goal_filters_by_participant_and_status` — only active current participant goal is returned.
- `tests/test_participant_sheets_gateway.py::test_list_planned_steps_filters_by_participant_and_goal` — planned steps are scoped.
- `tests/test_participant_sheets_gateway.py::test_list_weekly_status_history_filters_by_participant` — weekly history is scoped.

## Acceptance Criteria

- [ ] Telegram ID identity lookup is exposed through Sheets gateway.
- [ ] Consent writes go through Sheets gateway and update `consent_given` plus `consent_given_at`.
- [ ] Goal, planned-step, and weekly-history reads are scoped by participant ID.
- [ ] Fake gateway remains deterministic and does not expose mutable internal rows.
- [ ] Existing foundation boundary tests still pass.
- [ ] No SQLite business storage or live Google API adapter is added.
