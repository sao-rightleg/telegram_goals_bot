# Task 5: Read-only participant views

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Implement goal, planned-steps, progress, and inert out-of-scope menu action handling for known consenting users. This gives participants useful read-only access while preserving scope boundaries.

## What to do

- Add service handling for goal, planned-steps, progress, insight placeholder, and captain-only placeholder menu actions.
- Re-resolve Telegram ID through Sheets for every protected action.
- Require consent before returning participant business data.
- Scope goal, planned-step, and progress reads to the current participant.
- Calculate planned-step progress and render weekly status history only as secondary information.
- Route missing required data to safe user copy plus admin technical notification.

## TDD Anchor

Tests to write BEFORE implementation. Write → run → confirm they fail → write code → confirm they pass.

- `tests/test_participant_views.py::test_goal_view_shows_current_participant_goal_only` — goal view is scoped.
- `tests/test_participant_views.py::test_steps_view_shows_current_participant_steps_only` — step view is scoped and read-only.
- `tests/test_participant_views.py::test_progress_view_uses_planned_steps_as_primary_progress` — progress calculation is based on planned steps.
- `tests/test_participant_views.py::test_weekly_history_is_secondary_when_available` — weekly history is not the primary percent source.
- `tests/test_participant_views.py::test_view_requires_consent_before_data` — no data before consent.
- `tests/test_participant_views.py::test_missing_goal_sends_safe_message_and_admin_error` — missing data path is safe.
- `tests/test_participant_views.py::test_out_of_scope_actions_are_inert` — insight/captain placeholders do not write business facts.

## Acceptance Criteria

- [ ] Goal view shows only current participant goal title, description, value, and permission condition.
- [ ] Planned-steps view shows current participant open and closed steps without creating steps.
- [ ] Progress view shows a 6-cell planned-step progress bar and percent.
- [ ] Weekly status history is optional secondary information.
- [ ] Protected actions do not return data before consent.
- [ ] Missing required data does not crash and routes a technical admin notification.
- [ ] Inert actions do not create weekly reports, insights, PDFs, scheduler jobs, or voice records.
