# Task 5: Captain boundary regression coverage

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add cross-flow regressions for forged participant IDs, dropped participants, duplicate reports, deadline denial, invalid step selection, and out-of-scope dependency boundaries. This protects captain manual reports from role leakage and business-rule bypass.

## What to do

- Add behavior tests for captain forbidden selections and role boundaries.
- Add tests for dropped participants and duplicate reports.
- Add tests for deadline denial and invalid step selection.
- Add dependency/import boundary assertions if needed.
- Ensure generated secrets/audio/database artifacts are not introduced.

## TDD Anchor

Tests to write BEFORE implementation or to confirm existing implementation:

- `tests/test_captain_boundaries.py::test_forged_other_team_participant_id_is_rejected` — forged target id cannot leak or save report.
- `tests/test_captain_boundaries.py::test_dropped_participant_manual_report_is_rejected` — dropped target cannot be reported.
- `tests/test_captain_boundaries.py::test_captain_manual_report_after_deadline_is_rejected` — late finalization creates no report.
- `tests/test_captain_boundaries.py::test_invalid_or_closed_step_selection_is_rejected` — invalid step IDs do not save progress.

## Acceptance Criteria

- [ ] Forged other-team participant IDs are rejected server-side.
- [ ] Dropped participant manual reports are rejected.
- [ ] Duplicate report attempts create no new weekly report or step relation.
- [ ] Late captain manual report attempts create no status-changing report.
- [ ] Invalid selected steps are rejected.
- [ ] Other-team participant names/text do not appear in user-visible denial responses.
- [ ] No new out-of-scope runtime dependency is introduced.
