# Task 3: Captain team view service

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add captain service behavior for resolving captain identity, consent, role, and own-team participant list. This gives captains the team visibility required for manual report selection while denying non-captains and cross-team access.

## What to do

- Add `CaptainService` or equivalent captain-specific service module.
- Resolve captain identity through Telegram ID and consent.
- Require `role = captain` and non-empty `team_id`.
- List only participants with the captain's team id.
- Return safe Russian Telegram responses through the main bot boundary.
- Route missing/invalid technical state to admin error chat where appropriate.

## TDD Anchor

Tests to write BEFORE implementation:

- `tests/test_captain_team_flow.py::test_captain_can_view_only_own_team` — own-team response includes own-team participants and excludes other teams.
- `tests/test_captain_team_flow.py::test_non_captain_cannot_view_team` — non-captain gets safe denial and no data leak.
- `tests/test_captain_team_flow.py::test_captain_without_team_routes_missing_data_to_admin` — missing team id is safe for user and reported to admin.

## Acceptance Criteria

- [x] Only consenting identified captains can use captain team view.
- [x] Non-captains cannot use captain team view.
- [x] Captain team view includes only rows with captain `team_id`.
- [x] Other-team participants are not present in visible text.
- [x] Missing captain team data returns safe user copy and admin technical notification.
- [x] Unknown users keep existing unknown-user behavior.
