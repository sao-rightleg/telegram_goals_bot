# Task 1: Weekly report message and status contracts

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add feature-level status mapping and Russian message helpers for weekly report prompts, validation errors, voice rejection, and success confirmations. This gives later service code a stable copy and status contract without live Telegram wiring.

## What to do

- Add weekly report status contracts for `green`, `blue`, and `red`.
- Expose symbol and score mapping for each status.
- Add Russian message helpers for weekly report start, status prompts, selected-step requirements, empty text, late report, duplicate report, voice not available, recovery, and success confirmations.
- Keep all contracts testable without Telegram SDK, Google Sheets, SQLite, network access, or production secrets.
- Do not add weekly report service orchestration in this task.

## TDD Anchor

Tests to write BEFORE implementation. Write → run → confirm they fail → write code → confirm they pass.

- `tests/test_weekly_report_messages.py::test_weekly_report_status_mapping_matches_spec` — green/blue/red expose approved symbol and score mapping.
- `tests/test_weekly_report_messages.py::test_weekly_report_status_buttons_match_user_spec` — start/status buttons contain `🟩 Победа есть`, `🟦 Частично`, and `🟥 Победы нет`.
- `tests/test_weekly_report_messages.py::test_weekly_report_success_messages_match_spec` — green, blue, and red success copy matches user-spec.
- `tests/test_weekly_report_messages.py::test_weekly_report_validation_messages_are_short_and_safe` — validation copy is Russian, short, and does not expose schema names or secrets.
- `tests/test_weekly_report_messages.py::test_voice_not_available_message_does_not_create_voice_state_contract` — voice rejection is copy-only.

## Acceptance Criteria

- [ ] Status mapping exposes `green` / `🟩` / `1`, `blue` / `🟦` / `0.5`, and `red` / `🟥` / `0`.
- [ ] Russian weekly report copy follows approved short, calm Telegram tone.
- [ ] Status buttons match the user-spec labels.
- [ ] Success confirmations match the user-spec.
- [ ] Validation messages do not expose internal schema names, secrets, or unrelated participant data.
- [ ] No live Telegram SDK, Sheets writes, SQLite writes, voice processing, scheduler, PDF, deploy, or service orchestration is added.
