# Task 2: Insight Sheets Boundary

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Extend the Sheets protocol and fake gateway with participant-scoped insight list/get operations and final row expectations for `insight_title` and `insight_date`. This keeps final Insight facts inside the approved Google Sheets boundary and prevents cross-participant full-text access.

## What to do

- Add participant-scoped insight list and lookup methods to `SheetsGateway`.
- Implement the methods in `FakeSheetsGateway` using defensive copies.
- Preserve existing `append_insight` and `list_insights` behavior used by existing tests.
- Add tests for participant scoping, missing insight lookup, defensive copies, and new final-row fields.
- Do not add a live Google API adapter, credentials, network access, or production Sheet access in this task.

## TDD Anchor

Tests to write BEFORE implementation. Write → run → confirm they fail → write code → confirm they pass.

- `tests/test_insight_sheets_gateway.py::test_lists_insights_for_current_participant_only` — scoped list excludes other participants.
- `tests/test_insight_sheets_gateway.py::test_get_participant_insight_requires_participant_scope` — full lookup requires both participant ID and insight ID.
- `tests/test_insight_sheets_gateway.py::test_insight_rows_include_title_and_date_fields` — fake stores final row fields without mutation.
- `tests/test_insight_sheets_gateway.py::test_existing_insight_append_and_list_behavior_is_preserved` — old fake behavior still works.

## Acceptance Criteria

- [ ] Gateway exposes participant-scoped insight list/get operations.
- [ ] Fake gateway returns defensive copies.
- [ ] `insight_title` and `insight_date` are supported in final rows.
- [ ] Existing fake insight append/list tests remain valid.
- [ ] No live Google API adapter or credentials are introduced.
