# Task 3: SQLite technical-state schema

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Implement SQLite schema initialization for technical state only. The result must support dialog/draft/scheduler/reminder/error state and must not create business-primary storage.

## What to do

- Implement SQLite schema initialization using the standard library.
- Create only technical-state tables from the approved schema.
- Provide a small API to initialize and inspect schema state.
- Add tests proving business-primary tables are not created.

## TDD Anchor

Tests to write BEFORE implementation. Write → run → confirm they fail → write code → confirm they pass.

- `tests/test_sqlite_schema.py::test_init_creates_required_technical_tables` — all required technical tables exist.
- `tests/test_sqlite_schema.py::test_init_does_not_create_business_primary_tables` — participants/goals/weekly reports business tables are not created.
- `tests/test_sqlite_schema.py::test_init_is_idempotent` — running schema init twice succeeds.

## Acceptance Criteria

- [ ] SQLite schema initializer creates required technical-state tables.
- [ ] Schema initialization is idempotent.
- [ ] Business-primary storage tables are not introduced.
- [ ] Tests use temporary SQLite databases.
