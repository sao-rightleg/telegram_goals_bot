# Task 2: Settings and secret redaction

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add typed configuration loading from environment and optional `.env`, including three Telegram bot tokens and storage paths. Add redaction so diagnostic output cannot leak tokens or credential-like values. Timezone is intentionally not configurable in this task.

## What to do

- Implement a centralized settings module.
- Support `.env` loading for local development.
- Validate required MVP environment variables.
- Represent main, error, and notification bot tokens separately.
- Require all three bot tokens in strict/runtime mode; missing any one of them is invalid.
- Do not add `APP_TIMEZONE` or any runtime timezone override to settings.
- Add redaction for token-like and credential-like values.
- Add logging setup that uses redacted configuration metadata.
- Keep raw environment values out of log records and diagnostic output.

## TDD Anchor

Tests to write BEFORE implementation. Write → run → confirm they fail → write code → confirm they pass.

- `tests/test_config.py::test_settings_load_from_fake_env` — complete fake env creates settings.
- `tests/test_config.py::test_missing_required_setting_fails_clearly` — missing required value produces useful validation error.
- `tests/test_config.py::test_strict_mode_requires_all_three_bot_tokens` — strict/runtime settings fail when any main/error/notification token is missing.
- `tests/test_config.py::test_secret_values_are_redacted` — token and credential-like values do not appear in redacted output.
- `tests/test_config.py::test_three_bot_tokens_are_distinct_settings` — main/error/notification bot tokens are separate fields.
- `tests/test_config.py::test_env_file_loading_does_not_require_real_secrets` — `.env` loading works with fake local values only.
- `tests/test_config.py::test_timezone_is_not_runtime_config` — settings do not expose an `APP_TIMEZONE` override.

## Acceptance Criteria

- [ ] Settings loader supports env variables from `.env` or process environment.
- [ ] `MAIN_TELEGRAM_BOT_TOKEN`, `ERROR_TELEGRAM_BOT_TOKEN`, `NOTIFICATION_TELEGRAM_BOT_TOKEN` are separate settings.
- [ ] Strict/runtime mode requires all three Telegram bot tokens immediately.
- [ ] Timezone is not loaded from `.env` or process environment.
- [ ] Secret values are redacted in diagnostics/logging.
- [ ] Tests do not require real tokens or Google credentials.

## Details

**Files:** `app/config.py` — settings loading and validation.  
**Files:** `app/logging.py` — logging setup and redaction integration.  
**Files:** `tests/test_config.py` — tests for config and redaction.

**Dependencies:** Task 1. Allowed new package: `python-dotenv` only if needed for local `.env` support.

**Edge cases:** Missing one, two, or all three tokens should fail clearly in strict/runtime mode, while tests should be able to use fake values. Redaction must handle exact secret values and common token-like strings. `APP_TIMEZONE` in the process environment must not affect scheduler behavior.

**Implementation hints:** Treat `.env` as local input only; never print complete settings objects unless they pass through a redaction function. Keep timezone in `app/scheduler/calendar.py`.
