# Task 3: Weekly report draft repository

## Required Skills

Before executing the task, load:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Add a SQLite repository for weekly report draft sessions, selected status/steps, ordered text messages, active draft loading, and draft clearing. The repository uses existing technical-state tables and must not create final business storage.

## What to do

- Add a repository over `draft_sessions`, `draft_reports`, `draft_messages`, and `dialog_states`.
- Create weekly report draft sessions with selected status and selected step metadata.
- Append text draft messages with deterministic message order.
- Load an active draft snapshot for a Telegram user.
- Clear draft/session/message/dialog state after successful save or unsafe recovery.
- Do not change the SQLite schema unless a test proves the existing approved schema cannot support the spec.

## TDD Anchor

Tests to write BEFORE implementation. Write → run → confirm they fail → write code → confirm they pass.

- `tests/test_weekly_report_draft_repository.py::test_create_weekly_report_draft_writes_technical_state` — draft session/report/dialog rows are created.
- `tests/test_weekly_report_draft_repository.py::test_append_text_messages_preserves_order` — final text is assembled by message order.
- `tests/test_weekly_report_draft_repository.py::test_update_status_and_selected_steps` — selected status and step IDs round-trip deterministically.
- `tests/test_weekly_report_draft_repository.py::test_clear_draft_removes_technical_state` — draft rows and dialog state are cleared.
- `tests/test_weekly_report_draft_repository.py::test_repository_does_not_create_business_tables` — no local final business table is introduced.
- `tests/test_weekly_report_draft_repository.py::test_missing_or_invalid_draft_returns_none_or_recoverable_error` — stale state is safe to recover.

## Acceptance Criteria

- [ ] Repository uses existing SQLite technical tables.
- [ ] Draft messages preserve insertion order.
- [ ] Selected status and selected step IDs are stored and read deterministically.
- [ ] Clearing a draft removes temporary weekly report draft state.
- [ ] Repository works with temp SQLite files and `initialize_schema`.
- [ ] No final WeeklyReport, WeeklyReportSteps, goal, participant, or planned-step business facts are stored as local source of truth.
